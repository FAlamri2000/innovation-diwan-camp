# Innovation Diwan camp operations — guide for agents

A standalone dashboard for the Innovation Diwan virtual camp on SoWork (README.md for what it does,
docs/operations.md for how, docs/deployment-cranl.md for production). Arabic-first, full RTL.

## Commands

```bash
npm run dev          # 127.0.0.1:8080 (reads .env). No SoWork sync unless CAMP_SCHEDULER=on
npm run typecheck    # the gate
npm run check:camp   # domain-logic assertions, plain node
npm run migrate      # apply db/migrations (also runs at container start)
npm run build        # production build; then `sh scripts/start.sh`
```

`src/routeTree.gen.ts` is generated by the router plugin when the dev server or build runs —
never edit it; after adding a route, start `npm run dev` once and commit the regenerated file.

## Rules

- **Authorization is the role guards** (`src/lib/auth/guards.ts`): every server function uses
  `.middleware([requireAuth])` then `requireViewer|requireEditor|requireAdmin(context)` before
  touching data. The database is reachable only from the server; there is no RLS layer behind you.
- **`*.functions.ts` ship to the client bundle**: import server-only modules (`*.server.ts`, `pg`)
  inside the handler with `await import(...)`, never at the top.
- **Pure logic in `src/lib/camp/*.ts`** (not `*.server.ts`) uses relative `.ts` imports and no `@/`,
  so `npm run check:camp` runs it under plain node. Never put real names in `scripts/qa/camp-logic.ts`.
- **Migrations are append-only.** The migrator checksums applied files and refuses to start if one
  changed. Add `db/migrations/000N_name.sql`; plain PostgreSQL (no Supabase roles or extensions
  beyond `gen_random_uuid()`).
- **Every UI string goes in both `src/i18n/en.ts` and `ar.ts`.** `ar` is typed
  `Record<MessageKey, string>`, so tsc fails on a missing Arabic key.
- **Logical CSS only** (`ms-/me-/ps-/pe-/start-/end-/text-start`); physical `ml-4` breaks Arabic.
  No letter-spacing on Arabic text.
- **Colours come from tokens in `src/styles.css`** (the identity guide's green 60% / purple 30% /
  yellow 10%); a new token goes in both `:root` and `.dark`.
- **Sending is off by default** and must stay that way in seeds: gongs and announcements pop up for
  the whole SoWork office.
- **Derived facts are never stored** (except `camp_naming_daily`, which is history): roles, account
  types, naming status, duplicates, room placement and attendance re-derive on read.
- **Server error messages that the user sees are dictionary keys** (`auth.error.*`,
  `users.error.*`); `errorMessage()` in `components/camp/camp-ui.tsx` translates them.

## Traps already paid for

- Nitro's node server loads the app on the first request, and closes (but never exits) on SIGTERM.
  `scripts/start.sh` warms it up so the in-process scheduler starts at boot, and the scheduler
  exits the process after a running tick finishes. Don't remove either half.
- SoWork library items start when recording starts, not with the meeting; most meetings have no
  topic. Match by containment + participant overlap (docs/operations.md).
- SoWork keeps events 72 h and an inbox subscription only holds events from its creation — event
  capture must be started from Settings on day one.
